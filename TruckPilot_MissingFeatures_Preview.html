Missing Feature #3
Backend — Payments Table + Load Status Field
The most important foundational piece. Without a real payments table, everything above cannot work correctly.
❌ Current Structure
loads table:
  contractorPaid: boolean
  contractorPaidDate: string
  driverPaid: boolean
  driverPaidDate: string
  driverReceived: boolean
  driverReceivedDate: string

// No payments table exists
// Status is scattered flags
// Bulk payments impossible
// No payment history records
✅ What Needs to Be Added
loads table (add field):
  payment_status:
   "completed" |
   "pending_payment" |
   "paid"

payments table (new):
  id: uuid
  owner_uid: string
  driver_uid: string
  amount: number
  date: string
  method: string
  loads_included: uuid[]
  created_at: timestamp
💡
When the owner confirms a payment in the modal, the app should: (1) insert a new row in payments, (2) update each selected load's payment_status to "paid", and (3) refresh the driver's dashboard. This way, reports and tax documents can filter by payment_status = "paid" only — which is what CRA requires.
Missing Feature #4
Reports — Income Based on Payments, Not Loads
Your CRA reports currently include all load earnings. The fix is to filter income to only include loads where payment_status = "paid".
❌ Current reports logic
const income = loads
  .filter(l => l.completed)
  .reduce((s, l) =>
    s + l.earnings, 0);

// ❌ Includes unpaid loads
// ❌ Wrong for CRA
// ❌ Shows money not received
✅ What it should be
const income = loads
  .filter(l =>
    l.payment_status === "paid"
    || l.driverReceived === true
  )
  .reduce((s, l) =>
    s + l.driverBasePay, 0);

// ✅ Paid only
// ✅ CRA-correct
// ✅ Real cash received
Summary
4 Things to Build, In This Order
Priority order based on what unlocks everything else.
1
Supabase: Add payment_status to loads + create payments table
Foundation for everything else. Without this, bulk payments and correct reports are impossible.
2
Owner Panel: "Create Payment" modal with driver select + load checkboxes + auto-sum
Replaces the per-load pay flow. One action pays multiple loads. Writes to the payments table.
3
Driver Dashboard: Paid vs. Unpaid split + smart insights + Payment History tab
Shows real received income vs. owed income. Reads from the payments table for accuracy.
4
Reports: Filter income by payment_status = "paid" only (CRA-correct)
Small change, huge impact. Makes your CRA tax documents legally accurate.
✅ Good news: Your app already has the per-load payment badges, the driver payment history in Reports, and the contractor payment history. The architecture just needs to be upgraded from per-load flags → a real payments system so bulk payments work and reports become CRA-accurate.
